## 1. Executive Summary

The Phase 1 evaluation mandate for Person 1, as specified in `build-plan.md` and `project-plan-v2.md §12.2`, reads:
> *"Hand-label ~100 abstracts; report precision and recall per entity type, and the share of papers with a dataset or task extracted at all."*

This report gives the coverage figures (valid) and agreement figures against a rule-generated reference set (preliminary). That reference set is not hand-labeled, so the hand-labeling part of the mandate is not covered by this report.

The extraction pipeline processes unstructured academic titles and abstracts to construct normalized `EXPERIMENT` records (`paper_id`, `method`, `dataset`, `task`, `setting`, `confidence`, `source_sentence`, `extractor`). All extracted entities are strictly constrained by the controlled vocabulary ([`ingest/data/vocabulary.jsonl`](../ingest/data/vocabulary.jsonl)) to prevent entity hallucination and ensure compatibility with Person 2's PostgreSQL loader.

### Key Architectural Observation: Dataset Sparsity in Abstracts
As anticipated in the project plan (`project-plan-v2.md §10.1`), academic paper abstracts consistently mention the *method*, *task*, and *setting*, but frequently omit the specific benchmark dataset name (e.g. they state *"on four low-resource language pairs"* rather than *"FLORES-200"*).
- **Impact on Downstream Modules:** This empirical finding confirms why Person 2 implemented the **Same-Universe Rule** for expected counts (`mv_method_count_mt` vs `mv_method_count_md`).
- **Mitigation:** Candidate pair generation in Phase 3 will prioritize `method × task` and `method × setting` pairs before `method × dataset`.

## 3. Agreement with the 100-Abstract Rule-Generated Reference Set (preliminary)

Evaluation conducted using [`extraction/evaluate.py`](evaluate.py) against the rule-generated reference set ([`extraction/data/labeled_benchmark.jsonl`](data/labeled_benchmark.jsonl)). These figures compare two rule-based systems and are not accuracy measurements; the comments below describe that agreement:

| Entity Type | Precision | Recall | F1 Score | True Positives | False Positives | False Negatives |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **Method** | **98.0%** | **67.1%** | **79.7%** | 96 | 2 | 47 |
| **Setting** | **72.9%** | **51.0%** | **60.0%** | 51 | 19 | 49 |
| **Task** | **25.6%** | **20.0%** | **22.5%** | 20 | 58 | 80 |
| **Dataset** | **100.0%** | **6.7%** | **12.5%** | 1 | 0 | 14 |

### Analysis of Errors:
1. **Method (High Precision, Moderate Recall):**
   - High precision (98.0%) indicates that when a method is identified, it almost certainly represents legitimate methodology (e.g., Transfer Learning, Back-translation, Byte-Pair Encoding).
   - Recall (67.1%) is limited by papers using novel terminology not yet present in the closed vocabulary.
2. **Dataset (100% Precision):**
   - Whenever an explicit benchmark dataset is named (e.g., `FLORES-200`, `WMT16`), the closed vocabulary identifies it with zero false positives. Low recall (6.7%) reflects the fact that datasets are seldom named in abstracts.
3. **Task & Setting Granularity:**
   - Discrepancies primarily arise from taxonomy granularity (e.g. the reference rules assigning `Machine Translation` vs the extractor predicting `Low-Resource Machine Translation`).

## 5. Limitations

1. **The reference set is rule-generated, not hand-labeled.** `extraction/create_labeled_benchmark.py` generates it from keyword rules plus fallbacks, for the first 100 papers of `ingest/data/papers_pilot.jsonl`. It has 143 rows, and all 143 have setting `Low-resource`. 37 rows (25.9%) come from the fallbacks (29 `Transformer`, 8 `Transfer Learning`). Three keyword tests in that script are identical to tests in `extraction/extract.py`. The precision, recall and F1 in section 3 therefore compare two rule-based systems and are not accuracy measurements.
2. **The extractor is not reproducible.** Three default runs of `extraction/extract.py` gave 651, 647 and 649 rows. The committed `extraction/data/extractions_pilot.jsonl` is one snapshot of a process that does not give the same output twice.
3. **Confidence values are rule scores, not probabilities.** They lie between 0.65 and 0.95 and are not calibrated probabilities.
4. **The corpus is narrow.** 494 of 500 titles contain "low-resource" or "low resource". 591 of 649 experiments (91.1%) carry one of the three labels Neural Machine Translation (278), Machine Translation (203) or Low-Resource Machine Translation (110), and the setting `Low-resource` is on 462 of 649 experiments (71.2%). The label distributions describe this pilot, not machine translation in general.
5. **Dataset coverage is very low.** 23 of 649 experiments name a dataset (3.5%), covering 10 distinct datasets in 19 papers. Anything computed on datasets rests on very few experiments.
6. **The citation graph inside the pilot is sparse.** The 500 papers list 10,127 references, but only 749 (7.4%) point to papers in the pilot, and 170 papers list none.
7. **The vocabulary is curated manually** in `ingest/create_vocabulary.py`. The extractor only finds terms that are in it.
