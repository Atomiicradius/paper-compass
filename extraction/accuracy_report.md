## 1. Executive Summary

This report fulfills the Phase 1 evaluation mandate for Person 1 as specified in `build-plan.md` and `project-plan-v2.md §12.2`, incorporating all revisions requested in teammate feedback (Items 1–7):
- **Corpus Scaling (Item 1):** Scaled from 500 to 2,000 papers across 6 OpenAlex concept streams, doubling internal citation density from 7.4% to **14.88%** (11,681 internal citation edges out of 78,513 total).
- **Taxonomy Consolidation (Items 3 & 7):** Merged fragmented machine translation labels into canonical `Machine Translation` while moving constraint qualifiers to `SETTING` (`Low-resource`, `Multilingual`, `Unsupervised`, etc.). Eliminated cross-type duplicate entries.
- **Rule-Generated Reference Set (Item 2):** 100 papers were sampled at random (`seed=42`) and labeled by keyword and regex rules (a "conservative" and an "inclusive" rule set), not by people. 86 of the 100 sampled papers had identical labels under both rule sets; this is not an inter-annotator agreement. 79 rows come from 60 papers; the other 40 sampled papers produced no row (see section 3).
- **Calibrated Extraction & Threshold (Item 4, O7):** Extraction confidence calibrated to $\ge 0.70$ with strict regex boundaries.
- **Short-Alias Filtering (Item 6):** Enforced case-sensitive word-boundary matching (`\b[A-Z]{2,3}\b`) for short acronyms, completely eliminating false lowercase substring collisions.
- **Dataset Sparsity Analysis (Item 5):** Empirically verified dataset reporting frequency (only 3.8% in abstracts), justifying prioritization of `method × task` and `method × setting` pairs for combination discovery.

### Key Architectural Observation: Dataset Sparsity in Abstracts (Item 5)
As observed in the pilot and re-confirmed across 2,000 papers:
- Only **40 of 1,055 experiment tuples (3.8%)** across 32 distinct papers (17 distinct datasets) explicitly name a recognized benchmark dataset (e.g. WMT, IWSLT, Europarl, SQuAD, GLUE) in their title or abstract.
- Authors rarely name benchmark dataset titles in abstracts; instead, they report resource conditions ("tested on 4 low-resource Indian languages", "in zero-shot bilingual settings") or model architectures.
- **Recommendation:** Combination detection must prioritize **`method × task`** and **`method × setting`** pairs (which have rich representation across 1,055 experiments) before requiring `method × dataset`.

### How the reference set was made (rules, not annotators):
- 100 papers were sampled with `seed=42` and labeled by two rule sets in `extraction/create_reference_set_v2.py`: "conservative rules" (a regex plus a stricter condition) and "inclusive rules" (the regex alone). No person labeled anything.
- 86 of the 100 sampled papers had identical labels under both rule sets; 14 differed (listed in `extraction/data/inter_annotator_disagreements.json`, a file name kept from before). This is **not** an inter-annotator agreement, because both rule sets use the same patterns.
- The reference set has **79 rows from 60 papers**. The other 40 sampled papers produced no row: they are dropped by the rule `if not consensus_tasks and not consensus_methods: continue`.
- The method labels use the same vocabulary and a similar regex style as the extractor, so method precision and recall (100%) are **circular and not an accuracy measurement**.

### What the numbers show (agreement between two rule sets):
1. **Method (100% precision, 100% recall):**
   - Circular: both sides search the same vocabulary with similar regexes, so they agree. This says nothing about how well methods are found in general.
2. **Dataset (100% Precision, 33.3% Recall):**
   - Zero false positives against the reference rules; the 6 misses are datasets the reference rules found and the extractor did not.
3. **Task (83.3% Precision):**
   - Consolidating into canonical `Machine Translation` removed the earlier collisions between `Neural Machine Translation` and `Machine Translation`.
4. **Setting (71.0% Precision):**
   - Differences occur mostly when generic words like "supervised" appear without being the main experimental regime.

## 6. Limitations

1. **The reference set is rule-generated (preliminary; not human-labeled).** `extraction/create_reference_set_v2.py` (earlier `generate_real_benchmark.py`) labels 100 sampled papers with keyword and regex rules; it has 79 rows from 60 papers, and 40 sampled papers produced no row. Its method labels use the same vocabulary and a similar regex style as `extraction/extract.py`, so method precision and recall (100%) are circular. The precision, recall and F1 in section 3 compare two rule-based systems and are not accuracy measurements. The earlier version of the reference set, for the first 100 papers (`create_labeled_benchmark.py`), is replaced by this one.
2. **The extractions were regenerated with the deterministic extractor.** The earlier committed `extraction/data/extractions_pilot.jsonl` (1,054 rows) was not reproduced by any of 12 `PYTHONHASHSEED` values: the old extractor gave 12 different outputs with 1,049 to 1,060 rows. The file was regenerated with the deterministic `extract.py` and the vocabulary in which `SMT` is no longer a task alias: it now has **1,055 rows** (old: 1,054) and the 12 seeds give one identical output. All figures in this report describe the regenerated file.
3. **Confidence values are rule scores, not probabilities.** They lie between 0.7 and 0.95 and are not calibrated probabilities.
4. **The corpus is still skewed toward one theme.** 494 of 2,000 titles still contain "low-resource" or "low resource" (24.7%). Machine Translation covers 621 of 1,055 experiments (58.9%), and 336 (31.8%) have no task. The setting `Low-resource` is on 462 experiments (43.8%). The label distributions describe this corpus, not machine translation in general.
5. **Dataset coverage is very low.** 40 of 1,055 experiments name a dataset (3.8%), covering 17 distinct datasets in 32 papers. Anything computed on datasets rests on very few experiments.
6. **The citation graph inside the corpus is still sparse.** The 2,000 papers list 78,513 references, of which 11,681 (14.88%) point to papers in the corpus.
7. **The vocabulary is curated manually** in `ingest/create_vocabulary.py`. The extractor only finds terms that are in it.
